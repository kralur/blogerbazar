## Что получит владелец

Компания (например, сеть кафе на 15 человек) работает командой: владелец приглашает сотрудников по одному,
каждый входит своим Telegram, в Mini App или в браузере на компьютере, и делает то, что разрешает его роль.
Всё видно в журнале: кто принял отклик, кто завершил сделку.

## Как система узнаёт, что человек из этой компании

Никак не угадывает: человека **приглашают изнутри**.

1. Компания прошла модерацию (как сейчас). Для корпоративного тарифа — знак «Проверенная компания»: модератор сверяет
   документы (ИНН/СТИР), чтобы никто не выдал себя за известный бренд.
2. Владелец (или админ) нажимает «Пригласить» → одноразовая ссылка на 48 часов `t.me/<бот>?start=join_<код>`.
3. Сотрудник открывает её: бот показывает «Компания … приглашает вас. Владелец увидит ваше имя и номер из Telegram»
   → «Попросить доступ».
4. Владелец получает сообщение и экран заявки: имя, @username, номер из Telegram (D41) → «Принять как Менеджер» /
   «Отклонить». Только после этого человек в команде.
5. Убрать сотрудника можно в любой момент — доступ пропадает сразу, его браузерные сессии закрываются.

Код в ссылке хранится только как хеш; одна ссылка — один человек; повторное открытие после принятия ничего не даёт.

## Роли

| | Наблюдатель | Менеджер | Админ | Владелец |
|---|---|---|---|---|
| Видит кампании, отклики, предложения, сделки компании | да | да | да | да |
| Создаёт и меняет кампании, решает по откликам, отправляет предложения | — | да | да | да |
| Ведёт сделки: завершение, цена, подтверждение публикаций, контакты, отзыв | — | да | да | да |
| Меняет профиль компании, фото, видимость | — | — | да | да |
| Приглашает и убирает сотрудников (кроме админов) | — | — | да | да |
| Убирает админов, передаёт компанию, тариф, удаление компании | — | — | — | да |

Владелец у компании ровно один. Отзыв от компании по сделке — один, кто бы из команды его ни оставил.

## Этапы

### A. Фундамент команды (без видимых изменений) — **нужна миграция**

- Новая таблица `business_members`: компания, Telegram id сотрудника, роль, статус (активен / удалён), кто пригласил,
  даты. Уникальность: один активный владелец на компанию; один человек — в одной компании (на старте; агентства с
  несколькими брендами — позже, вместе с переключателем компаний).
- Миграция заполняет таблицу точными данными: каждый нынешний владелец компании становится «Владельцем». Ничего не
  выдумывается.
- Новый общий помощник `BusinessAccess`: «пользователь активен, выбранная роль — Бизнес (правило 1), есть активное
  членство в неудалённой компании, роль не ниже нужной». Им заменяются все места, где компания ищется по Telegram id
  вызывающего: 14 прямых обращений и 26 через `DealAccess`, `CampaignManagementAccess`, `OfferAccess` — кампании,
  отклики, предложения, сделки и их результаты, отзывы, фото, профиль компании, видимость, рекомендации, контакты,
  жалобы, удаление аккаунта.
- Проверки «сам с собой» (предложение себе, отклик на свою кампанию, жалоба на свою компанию) сравнивают со **всеми**
  сотрудниками компании, а не только с владельцем.
- Поведение для всех нынешних пользователей не меняется: у каждой компании пока один сотрудник — владелец.
- Тесты: 31 файл тестов исходит из «один Telegram = одна компания»; общий тестовый двойник получает членство,
  добавляются тесты ролей и «чужая компания = 404».

### B. Работа в браузере — без миграции

- То же приложение (тот же код и адрес Mini App) открывается в обычном браузере. Вне Telegram вместо экрана «откройте
  в Telegram» — **«Войти через Telegram»**.
- Вход: сайт показывает QR-код и ссылку `t.me/<бот>/app?startapp=web_<код>`. Человек открывает её телефоном или в
  Telegram Desktop → открывается Mini App (запрос подписан Telegram) → экран «Войти в BloggerBazar в браузере?
  Chrome, Windows, 14:05» → «Войти». Браузер это видит и получает cookie. Код живёт 2 минуты, одноразовый, привязан
  к этому браузеру. Отдельные кнопки бота и смена настроек вебхука не нужны.
- Cookie `__Host-bb_web` (HttpOnly, Secure, SameSite=Strict), сессия в Redis (как у сайта-админки): 12 часов,
  выход после 2 часов простоя. Сообщение в бот о каждом новом входе в браузере; список браузеров и
  «Выйти везде» в Настройках.
- API принимает эту cookie **только** на действиях бизнеса (явный список), только у активного сотрудника компании,
  изменения — только с адреса самого приложения (проверка Origin). Mini App внутри Telegram работает как раньше.
  Запросы идут через nginx Mini App (`/api/` уже проксируется), поэтому cookie остаётся на одном адресе.
- В браузере роль всегда «Бизнес»; если в Telegram выбрана другая роль, вход предложит переключиться на «Бизнес».
- Широкий вид для компьютера (таблицы откликов и сделок) — отдельно, после первых отзывов бизнесов.

### C. Приглашения и экран «Команда» — **нужна миграция**

- Таблица приглашений (хеш кода, роль, срок, кто пригласил, кто попросил доступ, статус).
- Экран «Команда» в профиле компании (Mini App и браузер): сотрудники и роли, «Пригласить», заявки, смена роли,
  «Убрать», «Передать компанию».
- Отзыв: одна запись от компании на сделку (сейчас уникальность по человеку — меняется на сторону сделки).
- Ответственный в сделке: кто принял отклик или отправил предложение. Уведомления о сделке — ответственному и
  владельцу (предложение; ждёт решения владельца).
- Журнал действий компании: кампании, решения по откликам, предложения, цена, завершение, отзывы — с именем
  сотрудника. Сейчас действия бизнеса не журналируются вовсе.
- Удаление аккаунта: владелец с командой сначала передаёт компанию или убирает сотрудников (понятная ошибка, а не
  тихое удаление компании); сотрудник, удаливший аккаунт, просто выходит из команды. Блокировка сотрудника лишает
  его доступа, компания остаётся.

### D. Корпоративный тариф — небольшая миграция

- Тариф компании: «Обычный» / «Корпоративный», лимит сотрудников, срок. Включает администратор платформы на
  сайте-админке (после оплаты по счёту); онлайн-оплата — отдельное решение (D32, Click/Payme, инфраструктура).
- Знак «Проверенная компания» и проверка документов модератором.

## Где будет сайт

Рекомендация: свой домен — `bloggerbazar.uz` (лендинг), `app.bloggerbazar.uz` (приложение: Telegram и браузер),
`admin.bloggerbazar.uz` (админка). Корпоративные клиенты не доверяют `…up.railway.app`, ссылки постоянные, cookie у
каждого поддомена своя. Покупка домена и DNS — у владельца; до этого этап B работает на нынешнем адресе Mini App,
переезд потом — просто повторный вход.

## Порядок и объём

A → B → C → D. Каждый этап — отдельный пакет: CI с integration-тестами, проверка экранов на телефоне, выкладка по
одному. A — самый большой по коду (около 40 мест и 31 файл тестов), но без видимых изменений; миграции A, C и D —
каждая с отдельным согласованием. Пока идёт A, основной чат не трогает доступы бизнеса (`DealAccess`, кампании,
отклики, предложения, сделки), чтобы не мешать друг другу.

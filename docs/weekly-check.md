# Еженедельная автопроверка

Раз в неделю две вещи проверяются без участия человека:

1. **GitHub Actions «Weekly audit»** (`.github/workflows/weekly-audit.yml`): по понедельникам в 08:17 по Ташкенту
   (и вручную: Actions → Weekly audit → Run workflow) те же проверки уязвимостей прод-пакетов NuGet и npm, что в CI.
   Красный запуск значит, что в пакете, который уходит на прод, появилась известная уязвимость; GitHub присылает
   письмо о падении запуска по расписанию владельцу репозитория.
2. **Расписание Claude** (claude.ai → Routines): по понедельникам в 09:41 по Ташкенту отдельная сессия читает
   результат «Weekly audit», проверяет, что сайт-админка и API отвечают, считает открытые PR Dependabot и присылает
   отчёт из 4–8 строк с push-уведомлением.

## Как создать расписание Claude

Расписание, созданное из сессии Claude Code, запускается **без подключённого репозитория**: GitHub отвечает 403, и
проверки пакетов и Dependabot не выполняются (проверено двумя пробными запусками 2026-11-07). Поэтому расписание
создаёт владелец в claude.ai → Routines, выбрав репозиторий `kralur/blogerbazar`:

- Название: `BloggerBazar: еженедельная автопроверка`.
- Расписание: понедельник, 09:41, часовой пояс Asia/Tashkent.
- Репозиторий: `kralur/blogerbazar`, ветка `main`.
- Уведомления: push.
- Промпт: текст ниже целиком.

```text
Еженедельная автопроверка проекта BloggerBazar (репозиторий kralur/blogerbazar). Ничего не меняй в коде и не пушь:
только проверь и напиши владельцу короткий отчёт на русском.

Сделай три проверки:

1. Уязвимости в пакетах. В терминале:
   gh run list -R kralur/blogerbazar --workflow weekly-audit.yml -L 3 --json databaseId,status,conclusion,createdAt,event
   Это workflow «Weekly audit», он идёт по понедельникам в 08:17 по Ташкенту, то есть примерно за полтора часа до
   тебя. Если запусков нет или последний старше 2 дней, запусти сам:
   gh workflow run weekly-audit.yml -R kralur/blogerbazar --ref main
   и подожди завершения через send_later на 6 минут. Если последний запуск ещё идёт (status не completed), тоже
   подожди 6 минут и посмотри снова. Если conclusion не success, прочитай лог:
   gh run view <databaseId> -R kralur/blogerbazar --log-failed
   и выпиши названия уязвимых пакетов и их серьёзность. Если инструментов GitHub нет и gh отвечает 403, проверки 1
   и 3 пропусти и напиши об этом одной строкой со ссылкой
   https://github.com/kralur/blogerbazar/actions/workflows/weekly-audit.yml

2. Сайт-админка и API. В терминале:
   curl -sS -o /dev/null -w "%{http_code} %{time_total}\n" --max-time 20 https://admin-web-production-3072.up.railway.app/health
   curl -sS -o /dev/null -w "%{http_code} %{time_total}\n" --max-time 20 https://admin-web-production-3072.up.railway.app/api/admin-web/config
   Первый адрес отвечает nginx сайта-админки, второй проходит через него в API, так что 200 на втором значит, что
   API жив. Норма: оба 200 быстрее 3 секунд. При ошибке повтори один раз через минуту, прежде чем считать сбоем.

3. Dependabot. В терминале:
   gh pr list -R kralur/blogerbazar --state open --author app/dependabot --json number,title
   Посчитай PR и назови их заголовки, если их не больше пяти.

Отчёт: 4–8 коротких строк, без заголовков и таблиц, простыми словами. Первая строка: «Всё в порядке» или «Есть
проблемы». Дальше по одной строке на проверку: пакеты (чисто или какие уязвимости), сайт-админка и API (коды и
время), Dependabot (сколько PR ждут). Если что-то не так, добавь одну строку, что именно нужно сделать владельцу.
Не предлагай новых задач и не задавай вопросов.
```

После создания нажать «Run now» и убедиться, что в отчёте есть строка про пакеты с результатом, а не «не проверено».

## Что делать с отчётом

- «Всё в порядке»: ничего.
- Уязвимость в пакете: открыть PR Dependabot с обновлением этого пакета (если его нет, попросить Claude обновить
  пакет), дождаться зелёного CI, влить.
- Сайт-админка или API не отвечают: Railway → сервис → Deployments и Logs; обычно помогает Restart.
- PR Dependabot копятся: влить те, что зелёные (сначала прод-пакеты, dev-инструменты можно группой).

Лендинг и Mini App пока не пингуются: их адреса не записаны в документации. Чтобы добавить, вписать адреса в
пункт 2 промпта по образцу.
